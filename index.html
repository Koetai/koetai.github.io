SPARQL desktop

Contribute SPARQL examples without a GitHub account.

A browser app that lets researchers sign in with their ORCID iD, write or refine a SPARQL query against any endpoint in YummyData (with proxy support for HTTP/no-CORS targets), and submit working examples — or LLM-assisted requests for an expert — to the koetai/sparql-examples repository.

  • YASGUI editor + sparqljs keyword extraction
  • Curator role with PR-driven publishing
  • Affiliation capture with ROR identifiers

SPARQL examples

Curated, queryable, schema-checked example corpus.

A fork of sib-swiss/sparql-examples that aggregates the SPARQL queries submitted through the desktop and refined by curators. Every query lives as a self-describing Turtle file with inline prefixes; CI validates each example against an RDF4J SPARQL parser.

  • Multi-endpoint (UniProt, Wikidata, IDR, …)
  • Issue-driven, PR-reviewed contribution
  • Jekyll-rendered example browser

Scopoli

Learn SPARQL by solving biomedical problems.

A Rosalind-style tree of problems. Learners set up Python and their own triplestore, integrate Orphanet's ORDO, HOOM and OFCO rare-disease ontologies, query them, then move out to Wikidata, UniProt and RDF Portal. Every answer is checked live against a reference query on the same endpoint.

  • 48 problems in seven chapters, from Python to federation
  • Guides for Oxigraph, Fuseki, QLever, Virtuoso, GraphDB, Blazegraph and Comunica
  • Rare-disease data integration with ORDO, HOOM, OFCO and HPO

Koetai platform

FAIR SPARQL endpoints, multi-tenant.

A multi-tenant QLever deployment that lets research groups host their own SPARQL endpoint with ORCID-gated write access, ShEx/SHACL validation, and SPARQLList-style request bundling. Designed to make publishing a SPARQL endpoint as light as publishing a dataset.

  • Per-tenant QLever instance
  • ORCID auth for write operations
  • ShEx/SHACL shape validation
